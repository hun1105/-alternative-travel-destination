## 2. 세부 오퍼레이션 7종 상세 연동 명세

Plan B는 한국관광공사 관광데이터의 가치를 극대화하기 위해 총 7개의 세부 오퍼레이션을 유기적으로 연동합니다.

```text
[사용자 검색] ──▶ searchKeyword2
[반경 탐색]   ──▶ locationBasedList2 (주변 300m~3km 실시간 후보 수집)
[전국 확장]   ──▶ areaBasedList2 (전국 17개 시도별 관광지 수집)
[상세 정보]   ──▶ detailCommon2 (개요글, 대표 썸네일, WGS84 좌표)
[운영 검증]   ──▶ detailIntro2 (타입별 휴무일, 운영시간, 입장마감 필터링)
[비용/시설]   ──▶ detailInfo2 (입장료 무료/유료, 주차시설, 수유실)
[유사도 매칭] ──▶ categoryCode2 (대/중/소분류 매칭을 통한 대체재 점수화)
```

### [오퍼레이션 1] `locationBasedList2` (위치기반 관광정보 조회)
* **엔드포인트:** `/B551011/KorService2/locationBasedList2`
* **주요 파라미터:** `mapX`, `mapY`, `radius`(300~3000m), `contentTypeId`
* **서비스 내 역할:** 돌발 상황(비, 지연, 피로)이 발생한 현 위치를 중심으로 즉시 이동 가능한 반경 내 관광지 후보군을 실시간 추출합니다.

### [오퍼레이션 2] `areaBasedList2` (지역기반 관광정보 조회)
* **엔드포인트:** `/B551011/KorService2/areaBasedList2`
* **주요 파라미터:** `areaCode`, `sigunguCode`, `contentTypeId`
* **서비스 내 역할:** 서울 도심뿐만 아니라 부산, 제주 등 전국 단위 여행지에서 해당 지자체의 대표 관광지 풀을 구축하는 데 활용됩니다.

### [오퍼레이션 3] `searchKeyword2` (키워드 검색)
* **엔드포인트:** `/B551011/KorService2/searchKeyword2`
* **주요 파라미터:** `keyword` (URL 인코딩)
* **서비스 내 역할:** 메인 화면 상단 검색창에서 사용자가 장소명을 입력했을 때 실시간으로 공사 관광 데이터를 검색하여 일정에 추가합니다.

### [오퍼레이션 4] `detailCommon2` (공통정보 조회)
* **엔드포인트:** `/B551011/KorService2/detailCommon2`
* **주요 파라미터:** `contentId`, `defaultYN=Y`, `firstImageYN=Y`, `overviewYN=Y`, `mapinfoYN=Y`
* **서비스 내 역할:** 장소의 대표 이미지 썸네일, 공식 소개 개요글, 정확한 위경도 좌표를 추출하여 일정 카드와 지도 마커 팝업에 표출합니다.

### [오퍼레이션 5] `detailIntro2` (소개정보 조회)
* **엔드포인트:** `/B551011/KorService2/detailIntro2`
* **주요 파라미터:** `contentId`, `contentTypeId`
* **서비스 내 역할:** 관광타입별 운영시간(`usetime`), 정기 휴무일(`restdate`), 관람 소요시간 정보를 추출하여, 방문 시점에 문이 닫혀 있는 장소를 사전에 완벽히 걸러냅니다(하드 필터링).

### [오퍼레이션 6] `detailInfo2` (반복정보 조회)
* **엔드포인트:** `/B551011/KorService2/detailInfo2`
* **주요 파라미터:** `contentId`, `contentTypeId`
* **서비스 내 역할:** 입장료 정보(`infotext`), 주차 가능 여부, 유모차 대여 및 수유실 유무를 파악하여 사용자 예산 및 가족 적합성 점수를 산출합니다.

### [오퍼레이션 7] `categoryCode2` (서비스분류코드 조회)
* **엔드포인트:** `/B551011/KorService2/categoryCode2`
* **주요 파라미터:** `cat1`, `cat2`, `cat3`
* **서비스 내 역할:** 원래 방문하려던 장소와 후보 장소 간의 대분류(인문/자연 등), 중분류(역사/휴양 등) 일치 여부를 대조하여 '경험 유사성(가장 비슷한 대안)' 보너스 점수를 부여합니다.

## 3. 외부 API와의 융합 시너지 아키텍처

한국관광공사의 정적 관광 마스터 데이터는 실시간 외부 데이터와 결합하여 살아 숨 쉬는 의사결정 신호로 변환됩니다.

| 연계 외부 API | 제공 기관 | 융합 방식 및 시너지 효과 |
|---|---|---|
| **단기예보 API** | 기상청 (공공데이터) | LCC 투영법을 통해 WGS84 좌표를 기상 격자(X, Y)로 실시간 변환. 강수 및 폭염 시 공사 관광지의 실내/실외 적합성을 판정. |
| **실시간 인구혼잡도 API** | 서울시 (서울열린데이터광장) | 서울 115개 주요 관광 구역의 실시간 인구 밀집 신호(여유/보통/붐빔)를 TourAPI 관광지 좌표와 매핑하여 혼잡 회피 가중치 반영. |
| **보행자/차량 경로 API** | SK TMAP | 두 관광지 간의 실제 골목길 보행 소요시간 및 경사도를 계산하여 '도보 이동 가능 여부' 및 '연쇄 지연 위험' 정밀 예측. |

## 4. 성능 최적화 및 안정성 설계 (Fault-Tolerance)

### 4.1 SQLite 기반 TTL 스마트 캐싱
* **배경:** 공공 API의 반복 호출로 인한 트래픽 낭비와 응답 지연을 방지하기 위함.
* **구조:** SQLite3 기반의 경량 TTL(Time-To-Live) 캐시 계층(`SQLiteTTLCache`)을 구축.
  - 상세 관광정보(`detailCommon`, `detailIntro`): 24시간 캐싱 (변경 빈도 낮음)
  - 기상청 단기예보: 1시간 캐싱 (정기 예보 발표 주기)
  - 실시간 혼잡도: 10분 캐싱 (유동인구 변동 주기)
* **효과:** 동일 지역 재추천 시 외부 API 호출 없이 **50ms 이내 초고속 응답** 달성.

### 4.2 장애 격리 (Circuit Breaker & Graceful Fallback)
* 외부 API 서버(기상청, 혼잡도 등)에 일시적 장애가 발생하더라도 서비스 전체가 멈추지 않도록 설계되었습니다.
* 혼잡도 API가 응답하지 않으면 해당 항목을 '중립(0점)' 처리하고 TourAPI 관광지 본연의 거리/카테고리 점수로 안전하게 추천을 지속합니다.

## 5. 실시간 API 연동 헬스체크 증빙

서버 기동 시 `/health` 엔드포인트를 통해 모든 외부 공공 API의 정상 연동 상태를 실시간 검증합니다.

```json
{
  "status": "ok",
  "service": "Plan B 관광 추천 API",
  "integrations": {
    "tour_api": true,
    "weather_api": true,
    "walking_route_api": true,
    "car_route_api": true,
    "place_search_api": true,
    "crowd_api": true,
    "seoul_crowd_api": true,
    "seoul_transit_api": true
  }
}
```
* **검증 결과:** `tour_api: true`를 포함한 8개 전 부문 100% 정상 연동 확인 완료.
